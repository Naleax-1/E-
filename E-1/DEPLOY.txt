The official CspDebug app uses ac.connect() + ac.StructItem with an identical
layout on both ends and physics.startPhysicsWorker('CarDebugWorker', instanceKey,
callback). Its worker reads worker.input and calls physics.addForce(carIndex,
position, positionLocal, force, forceLocal). This DETOX path follows that shape.
Actual user CSP version and on-car behavior are NOT known to this sandbox.

INSTALL: Put DETOX.lua, DetoxPhysicsWorker.lua, manifest.ini, and Core/,
Definition/, Engine/, Model/, Observer/, Safety/, Send/, Verification/ together
in the CSP Lua app folder. Do NOT simultaneously deploy the older OPTIONAL
car_physics/script.lua in the same test: it is a separate unconnected physics
script and is not the Day 2 worker.

APP → PHYSICS WORKER path:
  E-12 State/Engine/Model/Solver → PhysicsOutput (read-only snapshot)
  → Safety.check → Send.worker_channel.publish (separate request buffer)
  → ac.connect keyed shared struct → DetoxPhysicsWorker.lua (worker.input
    session handshake, heartbeat, command sequence/ACK)
  → worker-side validity/FX bound/emergency/timeout/one-shot guard
  → physics.addForce(0, vec3(0,0,0), true, vec3(0,0,0.01), true).
No fictional transport. The previous Send.command_bridge.lua remains a command
facade; it only becomes ACTIVE after the actual worker's heartbeat is observed.
This is an APP Physics Worker, not the legacy car data physics script. Its
status is visible in the SAME app Observer via the shared struct.

Use, on a dedicated car and only after verifying CSP version and local +Z:
1. Run app, inspect TRANSPORT: ACTIVE and PHYSICS CONTEXT: PHYSICS_WORKER.
   WAITING_FOR_WORKER / CSP_WORKER_API_UNAVAILABLE / WORKER_START_FAILED means
   STOP. Never interpret an unacknowledged command as received.
2. Use script.detoxSendPing() if available to confirm ACK and matching seq.
3. Arm FX TEST in the app; wait for worker status ARMED and ACK matching seq.
   Arm itself applies NO force. The app-side controller remains DISABLED.
4. If authorized for diagnostic force testing, click the separate
   'Single 0.01 N pulse (ACK required)' button ONCE. It is never automatic.
   Worker consumes arm first and calls physics.addForce at most once; rearm is
   required for another pulse. The worker reports ADD_FORCE_RETURNED and an
   increasing addForceCalls counter only if API returns without error.
5. Observe PHYSICS RECEIVED, ACK, outputValid, workerStatus, requestedFX,
   preAddForceZ, appliedFX, addForceCalls separately. API return does NOT prove
   measurable change in AC vehicle state. Vehicle response remains NOT PROVEN.
6. Emergency button sets the shared emergency+disabled flags immediately;
   worker prioritizes them over normal commands. Clear Emergency is a separate
   explicit reset to disabled and requires a fresh Arm. If App stops updating,
   worker watchdog disables at 0.25 s. Do not rely on a UI control as a
   substitute for a physical abort procedure on a private test car.

Safety limit 150 N is unchanged; no FX generated by DETOX is applied directly.
App publishes only finite, validated output (Safety.check). Worker rejects
missing/invalid output, >600 N raw FX (existing hard overflow multiplier),
no heartbeat, emergency, missing arm, duplicate command seq, and unavailable
Force API. Fixed 0.01 N is NOT multiplied by computed FX. Full ENABLED remains
locked. No FY, FZ, Torque, Wheel, Suspension or Thermal injection.

Six-stage evidence, never collapse into one success flag:
1 App Command: sentSeq > 0 (attempt is NOT sufficient; matching ACK required).
2 Transport: worker tick with matching worker.input session; ACTIVE.
3 Reception: worker.received increased; ackSeq == sentSeq.
4 Safety: outputValid and worker status ARMED/ADD_FORCE_RETURNED, no fault.
5 Execution: worker status ADD_FORCE_RETURNED and addForceCalls incremented.
6 Vehicle response: independent same-session AC telemetry difference versus
  matched OFF baseline. 0.01 N may be below detection threshold. DO NOT claim
  vehicle effect or real AC success without an on-car recording.

App observer fields CURRENT STATE vs CREATE REASON vs LAST TRANSITION vs
LAST REJECTION must not be conflated. Existing trace samples use AC speed and
speed-derived acceleration; conditions between separate race runs do not prove
causality. Request actual CSP version, car script layout, same-session telemetry
and screenshots of all six stages. Mock tests validate only logic/SDK-shaped
calls, never an actual user installation or car response.

All Engine/Model/Solver physics formulas remain unchanged. The old optional
car_physics/script.lua still has no app bridge; do not infer its own API-call
counter from the new Physics Worker's counter.
